## Findings

1. **HIGH · R-02 (Hard Gate)** · `LoginModal.jsx:120` — em dash (U+2014) in sent-copy: "Check your inbox and spam folder — the link expires soon." Fix: period or comma ("...spam folder. The link expires soon.").
2. **HIGH · R-36 / C-5 (Hard Gate)** · `ResetPassword.jsx:134` — copy claims password history ("Use at least 8 characters you have not used on this account before") that Supabase does not enforce. Fabricated behavior claim. Fix: "Use at least 8 characters, and pick something you do not use on other sites." (advice, not enforcement claim).
3. **HIGH · R-32 (Hard Gate)** · `ResetPassword.jsx:163`, `LoginModal.jsx:219` — password-eye toggle carries `tabIndex={-1}`, so it is mouse-only and unreachable by keyboard (pattern copied from the pre-existing login eye button). Fix: drop `tabIndex={-1}` so the toggle enters the tab order.
4. **HIGH · R-25 (Hard Gate)** · `ResetPassword.jsx:139`, `LoginModal.jsx:139`, `LoginModal.jsx:179` — error banners use `text-red-600` on `bg-red-50`, measured ≈ 4.4:1, below AA 4.5:1 for normal text. Fix: `text-red-700` (≈ 5.9:1). Line 179 is pre-existing; the same pattern was propagated into the new views.
5. **HIGH · R-25 (Hard Gate)** · `ResetPassword.jsx:169,185` — field-error text uses `text-red-500` on white at `text-xs`, measured ≈ 3.8:1, below AA. Same pattern exists pre-existing in `LoginModal.jsx:197,225`. Fix: `text-red-600` at minimum (≈ 4.5:1) or `text-red-700`.
6. **HIGH · R-03 (Hard Gate)** · all four new submit buttons (`ResetPassword.jsx:113,191`, `LoginModal.jsx:125,161`) use `py-2` ≈ 36px tall, below the 44px minimum tap target. Value inherited from the app-wide button style (Login/Signup are also 36px). Fix: `py-2.5`/`py-3` on the new buttons, or apply app-wide.
7. **MEDIUM · R-32 (Hard Gate, pre-existing surface)** · `LoginModal.jsx` — the modal has no Escape-to-close handler; the new forgot view inherits it. Close button exists. Fix: `keydown` listener for Escape while open.
8. **MEDIUM · R-37 (Hard Gate, not violated)** · no `DESIGN.md` exists in the repo. Direction was inherited from the established app language (blue #0039a6, rounded cards, Tailwind, react-icons) rather than documented brand guidance. Recommendation: write a short `DESIGN.md` capturing that language so future UI work has explicit direction.
9. **LOW · R-34 (Quality Lock)** · `ResetPassword.jsx:92`, `LoginModal.jsx:119,139,179` — status/error chips use light-mode backgrounds (`bg-green-50`, `bg-red-50`) with no `dark:` variant; a light chip sits on the dark card. Readable and consistent with the existing app pattern. Fix if desired: `dark:bg-red-950 dark:text-red-300` equivalents.
10. **LOW · C-4 (Resilience)** · `ResetPassword.jsx:22-29` — a visitor who already has an active session but opens `/reset` without a recovery token gets the password form instead of the expired state (`PASSWORD_RECOVERY` never fired). Harmless (they can only change their own password) but not the intended state. Fix if desired: require a recovery marker before showing the form.

Observation outside scope (not numbered): `App.jsx:5,17,170` contain a pre-existing mojibake character in comments (encoding artifact, not UI copy). Untouched.
